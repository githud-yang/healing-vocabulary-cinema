# 🏗️ 治愈系单词放映机 - 系统架构说明

## 一、整体架构概览

这是一个多智能体协作系统，采用**分层流水线架构**：

```
┌─────────────────────────────────────────────────────────┐
│                    用户交互层                             │
│         (输入4个单词 → 接收故事 + 词汇卡)                  │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                   工作流调度层                            │
│        (config.json - 定义7步协作流程)                   │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                   智能体执行层                            │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │
│  │ WordAnalyzer│ → │ StoryWriter │ → │ StoryJudge  │     │
│  │  (分析)     │  │  (创作)     │  │  (评审)     │     │
│  └─────────────┘  └─────────────┘  └─────────────┘     │
│         ↑__________________________________↓            │
│              (评分<85分，反馈重写，最多2次)               │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                   输出呈现层                             │
│         (完整故事 + 词汇卡 + 评分反馈)                    │
└─────────────────────────────────────────────────────────┘
```

## 二、核心组件详解

### 1. 智能体层（Agents）

#### 🎬 **WordAnalyzer（词语拆解者）**
- **角色定位**：词汇分析师 + 意象构建师
- **核心职责**：
  - 分析4个单词的词源、词性、核心含义
  - 构建浪漫意象（视觉、情感、隐喻）
  - 设计故事融入方案（场景、情感、情节）
- **输出格式**：结构化的单词分析报告

#### ✍️ **StoryWriter（治愈系编剧）**
- **角色定位**：电影编剧 + 英语教师
- **核心职责**：
  - 创作400-600字的治愈系爱情故事
  - 将单词自然融入场景（招牌、歌词、书信等）
  - 生成词汇卡（音标 + 释义 + 记忆联想）
- **核心约束**：
  - **绝不生硬中英夹杂**
  - 单词必须作为场景元素出现
  - 粗体标注所有单词
  - 追求新海诚/《爱乐之城》的电影质感

#### ⚖️ **StoryJudge（放映机评委）**
- **角色定位**：电影评论家 + 教育专家
- **核心职责**：
  - 5维度评分（词汇融入度、电影感、情感治愈力、文艺质感、格式规范）
  - 提供具体改进建议
  - 判定是否通过（85分为及格线）
- **重写机制**：低于85分触发重写，最多2次

### 2. 工作流层（Workflow）

工作流定义了7个步骤的协作流程：

```
Step 1: 词语拆解
    ↓ 输出：word_analysis
Step 2: 故事创作  
    ↓ 输出：story
Step 3: 质量评审
    ↓ 输出：judgment (score, feedback)
    ↓ 如果 score < 85 且 rewrite_count < 2
Step 4: 故事重写（第一次）
    ↓ 输出：story (改进版)
Step 5: 重新评审（第一次）
    ↓ 输出：final_judgment
    ↓ 如果 score < 85 且 rewrite_count < 1
Step 6: 故事重写（第二次）
    ↓ 输出：story (最终版)
Step 7: 最终评审
    ↓ 输出：final_judgment
```

**条件控制**：
- 使用 `condition` 字段控制步骤执行
- `score < 85` 判断是否重写
- `rewrite_count` 控制重写次数上限

### 3. 数据流层（Data Flow）

```
输入数据：
{
  "words": "serendipity ephemeral luminescence ethereal",
  "rewrite_count": 0
}

中间数据流：
Step 1 (WordAnalyzer) 
  → word_analysis: 详细的单词分析报告
  
Step 2 (StoryWriter)
  → story: 完整的故事文本 + 词汇卡
  
Step 3 (StoryJudge)
  → judgment: {score, feedback, passed}

输出数据：
{
  "final_story": "故事内容",
  "score": 94,
  "feedback": "评审意见",
  "rewrite_count": 0
}
```

### 4. 质量控制机制

#### 评分体系（满分100分）
| 维度 | 分值 | 评估标准 |
|------|------|----------|
| 词汇融入度 | 25分 | 单词是否自然融入场景 |
| 电影感与画面感 | 25分 | 光影、色彩、感官描写 |
| 情感治愈力 | 25分 | 温暖、治愈、结局力量 |
| 文艺质感 | 15分 | 语言优美程度 |
| 格式规范 | 10分 | 标题、正文、词汇卡完整性 |

#### 重写循环
- **触发条件**：评分 < 85分
- **最大次数**：2次
- **改进策略**：根据评委反馈针对性修改

## 三、技术架构特点

### 1. **多智能体协作模式**
- **分工明确**：每个AI Agent有专业领域
- **流水线处理**：输出作为下一步输入
- **反馈闭环**：评委反馈驱动改进

### 2. **声明式配置**
- 所有逻辑在 `config.json` 中定义
- 无需编写复杂代码
- 易于修改和扩展

### 3. **模板化提示词**
- 每个AI Agent有独立的 `.prompt` 文件
- 包含角色定义、输出格式、示例
- 便于调优和版本管理

### 4. **条件工作流**
- 支持基于条件的步骤执行
- 实现质量控制循环
- 灵活应对不同场景

## 四、创新点总结

1. **教育 + 文艺 + 技术** 的跨界融合
2. **情境记忆法**：单词在故事中"活"起来
3. **电影级美学**：追求画面感和情感共鸣
4. **自动化质控**：5维度评分 + 重写机制
5. **零代码配置**：纯声明式架构

## 五、扩展性设计

- **新增AI Agent**：可在配置中添加
- **修改工作流**：调整 workflow 数组
- **自定义评分**：修改 story_judge.prompt
- **更换风格**：调整 story_writer.prompt 的风格描述
